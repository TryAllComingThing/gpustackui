# Codex 任务契约

每个进入实现的 Codex 任务必须填写以下内容。

## 必填字段

| 字段 | 要求 |
|---|---|
| 目标 | 一句话描述用户可见结果。 |
| 非目标 | 明确不修改的页面、API、权限或主题。 |
| 验收标准 | 可执行、可观察、可测试。 |
| API 契约 | 端点、请求、响应、错误码、分页/筛选/排序。 |
| 设计参考 | 组件、Token、主题、状态矩阵或截图。 |
| 允许修改路径 | 文件或目录 allowlist。 |
| 测试命令 | unit、E2E、visual、accessibility、build 中适用的命令。 |
| 证据路径 | 报告、截图、日志或质量产物路径。 |
| 风险与回滚 | 风险等级、回滚方式和需要人工批准的事项。 |

## 开始条件

- 没有 API 契约时，只能做结构或 Schema，不得虚构请求。
- 认证/权限契约已冻结；启用 `requiresAuth`、`requiresAdmin` 或 `permissions` 前，仍必须提供登录路由、回跳行为和浏览器证据。
- 没有验收标准时，不得进入页面实现。
- 设计变更未批准时，必须标记 `PROPOSED` 或 `PENDING`。

## 结束条件

任务只有在 `docs/ai/DEFINITION-OF-DONE.md` 的适用项全部满足后才能报告完成。
