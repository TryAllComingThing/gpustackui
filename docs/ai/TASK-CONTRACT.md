# Codex 任务契约

每个进入实现的 Codex 任务应填写以下内容。

## 必填字段

| 字段 | 要求 |
|---|---|
| 目标 | 一句话描述用户可见结果。 |
| 任务级别 | `L1`、`L2` 或 `L3`，遵循 `docs/ai/TASK-LEVELS.md`；高风险变更不得降级。 |
| 非目标 | 明确不修改的页面、API、权限或主题。 |
| 完成条件 | 可观察、可测试的结果。 |
| API 契约 | 端点、请求、响应、错误码、分页/筛选/排序。 |
| 设计参考 | 组件、Token、主题、状态矩阵或截图。 |
| 允许修改路径 | 文件或目录范围。 |
| 复用依据 | 已检索的组件、Composable、Utils、Service 候选，以及复用、扩展或新增理由。 |
| 测试命令 | unit、integration、E2E、showcase、accessibility、build 中适用的命令。 |
| 风险 | 对认证、权限、API、主题、性能或兼容性的影响。 |

## 开始条件

- 没有 API 契约时，只能做结构、Schema 或占位，不得虚构请求。
- 修改 guard、登录/退出、回跳或 `401/403` 行为前，先读取认证与权限文档，并保持后端独立授权语义。
- 没有明确完成条件时，不进入页面实现。
- 设计变更先写入 ADR，再修改 Token 源或运行时。

## 结束条件

- 目标行为已实现，变更范围与任务契约一致。
- 受影响的类型检查、Lint、测试或构建已执行，并在交付说明中列出实际结果。
- 文档、i18n、路由、API 契约和测试已按影响同步。
- 未执行项和已知风险已如实说明。
