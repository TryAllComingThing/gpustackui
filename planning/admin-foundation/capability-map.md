# 能力地图

- 变更 ID：`admin-foundation`
- 状态：`PROPOSED / ALL PRODUCT DECISIONS CONFIRMED`
- 评审状态：`R4 PRODUCT DECISIONS CONFIRMED / TECHNICAL GATES PENDING`
- 开发授权：`CONTRACT ADAPTER ONLY / PRODUCTION DENIED`
- 决策源：`decision-log.md`；本文只描述能力边界，不创造新决策。
- 目标：描述管理平台 MVP 的用户可见能力、优先级、依赖、状态和验收边界。
- 非目标：不实现页面、不新增真实 API、不定义最终视觉稿、不引入高级 ABAC/ReBAC、第一期不默认包含复杂批量导入导出和审批流。
- 同步基线：已按 v0.2 的多租户、用户单机构、单根四级、`active/inactive`、RBAC + 四种标准机构数据范围和 `permissions_version/session_version` 校正。

## 1. 当前框架基线

| 能力 | 当前状态 | 结论 |
|---|---|---|
| HttpOnly Cookie 会话 | 已实现 | 继续使用，不改为前端持久化 Token |
| 登录/退出/改密 | 已实现 | 作为 AUTH 基线 |
| SSO 入口 | 仅按 `/auth/config` 展示入口和可信退出 | 不代表已实现 OIDC/SAML 协议、账号绑定和组映射 |
| 路由保护与 `401/403` | 已实现 | 后续权限模型必须继续失败关闭 |
| CSRF | 已实现生产失败关闭 | 所有状态变更请求必须覆盖 |
| 管理员判断 | 仅有 `is_admin` | 不足以支撑角色、权限目录和机构数据范围 |
| 租户上下文 | 未实现 | `tenant_id` 必须由服务端会话或受信网关注入，普通 API 不接受客户端任意切换 |
| 身份绑定 | 未实现 | 业务用户与 IdP 身份分离，使用 `issuer + subject` 绑定；禁止按邮箱自动绑定 |
| 表格/表单/反馈模式 | 已有 `UDataTable`、`DataTablePattern`、`ComplexFormPattern` | 页面优先复用，不另建后台组件体系 |
| SSO/角色/字典/公告/审计 API | 未定义 | 必须先做契约，不能以生产 fixture 冒充 |
| 机构 API | R5 契约适配层已实现，依据后端交接草案 | 可做契约测试；生产页面、路由和真实联调仍未放行 |

## 2. 能力优先级定义

| 优先级 | 定义 |
|---|---|
| P0 | 管理平台基础链路；没有它无法安全上线 |
| P1 | MVP 完整体验和日常运营所需 |
| P2 | 规模化、审计分析或复杂组织场景再引入 |
| OUT | 明确不进入第一期，避免范围膨胀 |

## 3. 横切能力

| ID | 优先级 | 能力 | 用户可见结果 | 关键约束与依赖 |
|---|---|---|---|---|
| AUTH-01 | P0 | 本地账号登录 | 用户可通过用户名/密码建立会话 | 继续使用 HttpOnly Cookie、CSRF 和会话确认 |
| AUTH-02 | P0 | SSO 入口展示 | 后端声明 OIDC/SAML 可用时展示入口 | 首期必须接入 IdP；优先企业现有 IdP，否则 Keycloak；当前只展示链接，完整协议和回调由 IdP/后端实现 |
| AUTH-03 | P0 | 会话确认、过期和重试 | 会话失效回登录；服务异常进入不可用页 | `401` 与网络/服务错误严格区分 |
| AUTH-04 | P0 | 统一 `401/403` | 未登录与无权限得到不同结果 | 前端守卫不是授权边界 |
| AUTH-05 | P1 | SSO 账号绑定/JIT/组映射 | 外部身份可安全绑定到业务用户 | 使用 `issuer + subject`；禁止按邮箱自动绑定；首期不开放 JIT，仅允许邀请绑定 |
| AUTH-06 | P0 | 会话撤销与失效 | 停用、改密、解绑或安全事件后旧会话失败关闭 | `session_version` 独立于 `permissions_version`；版本不匹配返回 `401`；具体存储待后端签收 |
| PERM-01 | P0 | 权限目录 | 管理员可查看可分配权限 | 权限码由研发维护；需要分组、名称和 i18n |
| PERM-02 | P0 | 角色管理 | 可创建、编辑、停用、分配角色 | 内置角色受保护；不能通过自由字符串制造权限 |
| PERM-03 | P0 | 机构数据范围 | 用户只能访问授权机构范围 | 首期只支持 `self`、`org`、`org_subtree`、`all`；`all` 仅限当前租户，平台级使用 `platform_all`；`custom` 延后 |
| PERM-04 | P0 | 有效权限计算与展示 | 用户可查看自己/目标用户的最终能力 | 后端计算；前端只消费确认后的能力或权限码 |
| PERM-05 | P0 | 防提权 | 管理员不能授予超出自身权限和范围的角色 | 后端强校验，前端提前提示 |
| PERM-06 | P0 | 权限变更生效 | 角色/机构/范围变化后旧权限不能长期有效 | 使用 `permissions_version` 使授权快照失效；与 `session_version` 分开；缓存键包含 `tenant_id + user_id + permissions_version` |
| TENANT-01 | P0 | 租户自助管理 | `tenant_admin` 可管理当前租户的组织、用户、租户级角色、字典、公告和审计查询 | 仅限当前租户 `all`；禁止 `/platform/*`、跨租户切换、平台管理员分配和租户创建/删除 |
| AUD-01 | P0 | 审计事件记录 | 所有高风险写操作可追溯 | 追加写；包含操作者、动作、资源、结果、requestId、时间 |
| AUD-02 | P1 | 审计查询 | 管理员可按条件查询操作日志 | 只读；服务端数据范围过滤；禁止业务修改/删除 |
| AUD-03 | P1 | 审计详情 | 可查看资源、结果和脱敏差异 | 不记录密码、Token、Cookie、完整敏感个人信息 |
| AUD-04 | OUT | 审计导出 | 首期不开放导出 | 不创建导出权限、按钮、API 或归档流程 |
| AUD-05 | P1 | 脱敏与保存策略 | 审计事件持久保存且不泄露敏感数据 | 只保存和查询；不开放归档或合规删除；主存储容量和完整性保护待后端/运维确认 |

## 4. 机构管理能力

| ID | 优先级 | 能力 | 主流程与约束 | 验收要点 |
|---|---|---|---|---|
| ORG-01 | P0 | 查看机构树 | 按权限加载租户内机构树；支持搜索、展开和查看停用机构 | 无权限节点不出现；搜索不突破数据范围；每租户一个根机构 |
| ORG-02 | P0 | 创建机构 | 选择 `active` 父机构，填写编码、名称、类型、排序 | 编码在租户内唯一；普通创建不得创建第二个根；写入审计 |
| ORG-03 | P0 | 编辑机构 | 修改名称、类型、排序、负责人等可变字段 | `code` 创建后不可修改；使用版本前置条件处理冲突 |
| ORG-04 | P0 | 移动机构 | 将机构移动到其他父节点 | 禁止移动到自身/后代；整棵子树移动后最大 4 级；写入审计并递增受影响用户权限版本 |
| ORG-05 | P0 | 停用与删除边界 | 首期只定义 `active/inactive`；不提供删除或恢复 | 根机构、活动子机构或活动成员等冲突显式返回；不定义删除 API、权限或按钮 |
| ORG-06 | P1 | 用户所属机构 | 查看和调整用户当前所属机构 | 用户当前仅属于一个机构；角色数据范围可覆盖子树，但不得解释为多机构成员关系 |
| ORG-07 | P2 | 机构批量移动/导入 | 批量改变层级 | 需要异步任务、部分失败语义和审计 |

|---|---|---|---|---|

| USR-09 | P2 | SCIM/离职同步 | 外部身份生命周期自动同步 | 需明确 IdP 主数据与停用规则 |

## 11. 开发前能力门禁

以下仍是规划事实，不是实现承诺：

- 机构 API 当前只有 v0.2 候选契约和 OpenAPI 提案，真实后端 OpenAPI 未确认，状态为 `NOT FREEZABLE`。
- 所有租户级能力必须由后端隐式注入并校验 `tenant_id`；前端不得从请求参数、角色名或菜单推导租户边界。
- 角色定义、平台跨租户入口、四种标准数据范围、租户自助管理、`tenant_admin`、只停用、审计仅保存和 HTML 原型均已确认产品边界。
- 后端真实 OpenAPI、租户级权限实现、最后管理员保护和技术签批仍是开发门禁。
- 数据字典、公告和审计 API 尚未定义，本能力地图不代表后端已存在这些端点。
- 后端真实 OpenAPI 和技术签批未完成前，不进入 `src/**` 实现。

## 12. 首批实现顺序建议

1. 机构读模型、创建、编辑、移动和启停约束。
2. 权限目录、角色、数据范围和有效权限。
3. 用户列表、创建/邀请、所属机构/角色分配和启停。
4. 数据字典类型与字典项。
5. 公告草稿、预览、发布和撤回。
6. 审计查询和详情。

审计事件模型必须在第 1 步前冻结；审计查询页面可以晚于业务写操作实现。每一切片都必须另立实现任务并获得开发授权。

## 13. 角色端到端任务闭环

能力存在不等于角色可以完成任务。以下矩阵用于检查“入口 → 权限 → 数据范围 → API → 状态 → 审计 → 原型”是否闭合；`BLOCKED` 表示不得进入实现。

| 角色 | 首要任务 | 入口与权限 | 数据范围 | 当前闭环状态 |
|---|---|---|---|---|
| 平台管理员 | 初始化租户、管理平台级身份和跨租户运维 | 独立 `/platform/*`；`platform:tenant:manage` | `platform_all`，目标租户显式记录 | `PARTIAL`：产品入口和角色归属已确认；平台授权载体与审计待技术签批 |
| 租户管理员 | 自助管理本租户机构、用户、租户级角色、字典、公告和审计查询 | `/system/*`、`/content/*`、`/audit/*`；租户管理权限 | 当前租户 `all` | `PARTIAL`：产品范围已确认；后端 API、角色实现和最后管理员保护未冻结 |
| 机构管理员 | 管理授权机构子树的用户和机构基础资料 | `/system/organizations`、`/system/users` | `org` / `org_subtree` | `PARTIAL`：机构 API 未冻结，用户/角色 API 未定义 |
| 审计员 | 查询和筛选审计事实，首期不导出 | `/audit/logs`；`audit:log:read/detail` | `org_subtree` / `all` | `PARTIAL`：产品范围已确认；审计存储与失败关闭待后端/安全签批 |
| 只读管理员 | 查看授权范围内管理数据，不执行写操作 | 各管理页读权限 | `org_subtree` | `PARTIAL`：读模型和 API 尚未冻结 |
| 普通用户 | 维护个人资料并离开管理导航 | `/account/profile`；`profile:self:*` | `self` | `PARTIAL`：需确认真实个人资料 API 与管理首页分流 |

闭环验收至少要求：

- 每个角色有明确入口、页面 ID、读/写权限和数据范围。
- 每项写操作有稳定 API、错误码、状态恢复、审计事件和权限版本影响。
- 无权限、范围外、空数据、版本冲突和服务异常均可观察且失败关闭。
- 复杂任务有 HTML 原型，并通过代码级键盘、窄屏和屏幕阅读器验收。
- 任一前置决策未关闭时，任务状态保持 `BLOCKED`，不能以页面 fixture 模拟完成。
