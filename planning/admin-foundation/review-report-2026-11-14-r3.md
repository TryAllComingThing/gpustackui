## 3. 阻断级与高优先级发现

### R3-01 决策证据链仍不能由具名负责人证明

**严重级别：** Blocker

**证据：**

- `decision-log.md` 已增加 `USER_CONFIRMED`，但来源仍主要是 `review-checklist.md`。
- `review-checklist.md` 又要求已确认项能追溯到决策日志。
- 当前没有具名决策人、审批日期、会议记录、邮件或签批文件。

**影响：** 无法证明产品、安全、后端或运维负责人已经批准 ADR、权限和 API 冻结。

**关闭条件：** 建立单向证据链：具名人工决策证据 → `decision-log.md` → ADR/权限/API/交互文档。每个要冻结的决策必须记录决策人、日期、范围和证据链接。

### R3-02 平台管理员跨租户身份载体仍不可实现

**严重级别：** Blocker

**证据：**

- `role-permission-matrix.md` 把 `platform_admin` 定义为 `platform_all`。
- `UserRoleBinding` 仍要求 `tenant_id`，无法无歧义表达全局平台身份。
- `/platform/*` 仍受 `MANUAL-05` 阻塞。

**影响：** 可能把平台管理员塞入普通租户绑定，或让普通租户 API 接受跨租户切换，形成租户隔离绕过。

**关闭条件：** 明确平台身份载体、独立入口、目标租户记录、平台审计字段和普通 API 禁止跨租户规则；由 `MANUAL-05/06` 决策并安全签批。

### R3-03 IdP、JIT、破窗和身份生命周期未冻结

**严重级别：** Blocker

**证据：** `MANUAL-01/02/03` 均仍为 `OPEN`；ADR 只给出 OIDC 中介和 Keycloak 工程推荐，没有冻结 issuer、audience、回调、声明映射、JIT 关闭、破窗控制和 IdP 停用同步。

**影响：** SSO 回调、Token 校验、账号绑定、离职停用和故障恢复无法形成实现契约。

**关闭条件：** 关闭 `MANUAL-01/02/03`，明确现有 IdP 优先、JIT 策略、破窗网络/MFA/凭证/轮换/告警，以及 IdP 停用和最大会话分叉时延。

### R3-04 `custom`、防提权和最后管理员仍有授权漏洞

**严重级别：** Blocker

**证据：**

- `custom` 范围明细携带 `allowed_actions`，存在成为角色权限之外额外授权通道的风险。
- 防提权此前缺少可执行公式。
- 最后管理员保护未覆盖角色绑定到期、离职同步和批量撤销。

**本轮修订：**

- 明确 `allowed_actions` 只能收窄角色权限：`binding_permissions = role.permissions ∩ allowed_actions`。
- 增加 `effective_action` 与 `grantable_permissions` 判定式。
- 增加目标权限、目标范围和目标用户三重提交前断言。
- 角色绑定到期、离职同步、身份解绑和批量撤销必须经过同一保护断言。

**仍待关闭：** `MANUAL-04/06/07`，以及后端权限目录是否支持显式可委派性和 `PlatformAdminGrant` 最终模型。

### R3-05 审计导出与保留契约未形成

**严重级别：** Blocker

**证据：** 当前只有“导出单独授权且被审计”的原则，没有导出 API、字段白名单、最大行数、脱敏、下载凭证、审计事件、保留/归档/合规删除契约。

**影响：** 无法宣称审计导出满足安全、合规和可追溯要求。

**关闭条件：** 关闭 `MANUAL-09`，冻结导出请求/状态/下载、敏感字段策略、上限、保留、归档、合规删除和导出审计事件。

### R3-06 机构 API 幂等、锁和版本模型不可执行

**严重级别：** High，冻结 API 前升级为 Blocker

**证据：**

- 原契约把 `request_body_hash` 放入幂等唯一作用域，导致“同 key 不同 body”无法识别。
- 只有移动定义结构锁，创建和状态变更可与停用、移动并发破坏不变量。
- 移动只更新源子树用户，遗漏绑定范围或 `custom` 明细引用被移动机构的用户。

**本轮修订：**

- 拆分 `lookup_key` 与 `request_fingerprint`。
- 增加 `pending/succeeded/failed/expired` 状态、并发请求、重放优先级、`IDEMPOTENCY_IN_PROGRESS` 和 24 小时候选 TTL。
- 创建、移动、状态变更和根初始化统一进入租户结构串行化资源。
- 明确受影响用户集合为“主属机构用户 ∪ 角色绑定范围用户 ∪ `custom` 引用用户”。
- 增加单根数据库不变量、根保护、Outbox 状态机和 typed error code 候选。

**仍待关闭：** 后端确认隔离级别、锁超时/死锁重试、幂等记录存储与清理、真实 Outbox Schema 和最大投递时延。

### R3-07 页面契约与可访问性证据不完整

**严重级别：** High

**证据：** 原交互文档只有页面清单和原则性可访问性要求，缺少页面 ID、route name、导航父键、breadcrumb、动作权限、数据范围、API、状态责任和高保真门槛；错误状态仍使用 `409-A/409-B` 概念。

**本轮修订：**

- 新增 `page-contract-matrix.md`，补齐页面契约字段、`TBD` API 和 HF 门禁。
- 将 `409` 改为稳定业务错误码映射，区分 `400/409/412/428/429/5xx`。
- 增加机构树、用户 Drawer、权限矩阵、公告和审计的键盘、焦点、窄屏、live region 和状态验收。
- 增加页面和组件 REUSE / EXTEND / NEW 决策表。

**仍待关闭：** `MANUAL-11/12`、管理概览访问对象、真实 API 契约和高保真原型证据。

### R3-08 公告状态机和角色任务闭环曾不完整

**严重级别：** High

**证据：** 原公告状态只有单向字符串；角色定义没有展开为端到端任务。

**本轮修订：**

- 增加候选状态转换表，明确草稿、计划、发布、撤回、过期和预览快照分离，并标记受 `MANUAL-10` 约束。
- 能力地图增加平台管理员、租户管理员、机构管理员、审计员、只读管理员和普通用户的任务闭环矩阵。

**仍待关闭：** `MANUAL-04/05/06/10` 以及公告 API、审计 API 的真实契约。

### R3-09 管理概览访问对象不明确

**严重级别：** Medium

**证据：** `/` 规划权限仍为 `authenticated`，普通用户是否应进入管理概览没有决定。

**处置：** 已记录在 `page-contract-matrix.md`，列为实现前产品决策，不自行关闭。

### R3-10 机构垂直切片任务契约仍是骨架

**严重级别：** High

**证据：** `review-checklist.md` 的允许修改路径和测试命令仍为待定，复用依据有重复项，真实 API 尚未冻结。

**处置：** 保持骨架状态。完成 R4 修订、人工决策、真实 API 对齐和原型签收后，才能形成独立 L3 任务。
