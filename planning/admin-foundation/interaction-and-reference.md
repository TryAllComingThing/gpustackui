## 1. 能力优先级与 HTML 原型优先级分离

能力优先级表示是否进入首期产品范围；原型优先级表示哪个复杂页面需要先完成 HTML 原型。两者不能混用。

| 能力 | 能力优先级 | 原型优先级 | 实现前门禁 |
|---|---|---|---|
| 机构树查看、创建、编辑、移动、启停 | P0 | P0 | HTML 原型 + 后端 OpenAPI 冻结 |
| 用户管理、单机构归属、角色范围绑定 | P0 | P1 | HTML 原型 + 标准模式评审 |
| 角色与权限矩阵 | P0 | P0 | HTML 原型 + 权限矩阵技术评审 |
| 数据字典 | P1 | P1 | HTML 原型 + 标准模式评审 |
| 公告编辑、预览、发布、撤回 | P1 | P0 | HTML 原型 + 公告模型评审 |
| 审计查询与详情 | P1 | P0 | HTML 原型 + 仅保存边界评审 |
| 批量导入 | P1 | P2 | 后端任务和部分成功语义冻结后再设计 |
| 租户自助管理 | P0 | P1 | 复用 `/system/*`、`/content/*`、`/audit/*`；后端 OpenAPI 与租户级权限冻结后实现 |

普通 CRUD 复用现有 `DataTablePattern`、`ComplexFormPattern`、`UDataTable` 和 Nuxt UI 页面模式；不制作全量像素稿。

租户自助管理不新增租户创建、租户删除、计费或跨租户入口。`tenant_admin` 使用当前租户上下文访问既有管理页面，并与 `platform_admin` 的 `/platform/*` 能力完全分离。

## 2. 规划级页面清单、导航与权限

以下路径和页面名称是规划冻结值，不代表当前路由器已实现。

| 导航组 | 页面 | 规划路径 | 读权限 | 主要写权限 |
|---|---|---|---|---|
| 工作台 | 管理概览 | `/` | `authenticated` | — |
| 身份与权限 | 机构管理 | `/system/organizations` | `iam:organization:read` | `create/update/move/update-status` |
| 身份与权限 | 用户管理 | `/system/users` | `iam:user:read` | `create/update/update-status/change-organization/assign-role` |
| 身份与权限 | 角色管理 | `/system/roles` | `iam:role:read` | `create/update/update-status` |
| 平台配置 | 数据字典 | `/system/dictionaries` | `system:dictionary:read` | `create/update/update-status` |
| 内容中心 | 公告管理 | `/content/announcements` | `content:announcement:read` | `create/update/publish/withdraw` |
| 安全与审计 | 审计日志 | `/audit/logs` | `audit:log:read` | 无普通写权限 |
| 安全与审计 | 审计详情 | `/audit/logs/:eventId` | `audit:log:detail` | 无 |
| 个人中心 | 个人资料 | `/account/profile` | `profile:self:read` | `profile:self:update` |

导航规则：

- 导航按用户任务分组，不按后端 Controller 或数据库表分组。
- 机构、用户和角色同属“身份与权限”。
- 字典属于“平台配置”；公告属于“内容中心”；审计属于“安全与审计”。
- 普通用户默认不展示管理导航；个人资料和修改密码从个人中心进入。
- `tenant_admin` 可展示当前租户的管理导航，但不得出现租户切换器或 `/platform/*` 入口。
- 菜单可见性依赖权限码和数据范围，但菜单隐藏不能替代路由 guard 或后端授权。
- 面包屑、页面标题、空状态和错误状态必须与导航术语一致。
- 当前 `src/app/navigation/nav.ts` 从路由 `meta.nav` 派生；未知 `parentKey` 会抛错。未来接入导航时必须先完成父子键注册和测试。

## 3. 全局页面模式

### 3.1 标准列表页

- 一个页面只有一个主要动作；危险动作不与主要动作视觉同级。
- 筛选条件写入 URL 或可恢复状态；刷新后不无故丢失。
- 空状态区分“无数据”和“筛选无结果”。
- 服务端分页、筛选和排序；前端不得加载全量再过滤。
- 行操作允许溢出菜单；危险操作必须二次确认。
- 批量操作必须明确部分成功、失败行和重试语义。
- 状态不能只靠颜色表达，必须有文本或图标和可访问名称。
- 列表 `total` 只统计授权范围，不能泄露租户或范围外总量。

### 3.2 表单与编辑

- 普通、少于 8 个字段的编辑可使用 Modal。
- 字段多、上下文复杂或需要并排预览时使用右侧 Drawer 或独立页。
- 权限矩阵使用独立工作区，不塞入普通表单 Drawer。
- 保存、保存草稿、发布、确认移动和确认状态变更必须有不同文案。
- 关闭有未保存修改的 Drawer/Modal 必须提示并恢复焦点。
- 提交期间只禁用当前提交动作，不冻结整个页面。
- 服务端字段错误映射到字段；未知错误显示统一错误区和 `request_id`。
- 写操作不得自动重试，除非 API 明确提供幂等键且契约已评审。

### 3.3 详情与确认

- 简单对象详情可使用 Drawer。
- 审计事件、公告预览和复杂用户有效权限使用独立详情页或宽面板。
- 确认对话框必须说明对象、影响范围、不可逆性和后续结果。
- 删除、移动、启停、发布、撤回和权限变更不能只显示“确定吗？”。
- 权限不足时可以展示只读信息，但隐藏或禁用写入口；后端仍须独立拒绝。
- 确认按钮使用动作名，例如“确认移动”“确认停用”，不使用含糊的“确定”。

## 4. 页面状态矩阵

页面必须覆盖以下 8 类状态；`401` 由全局会话机制处理，不进入普通业务页错误态。

| 编号 | 状态 | 页面表现 | 禁止行为 |
|---:|---|---|---|
| 1 | 初始加载 | 骨架或局部 loading | 展示旧数据并假装已刷新 |
| 2 | 空数据 | 解释为什么为空并提供下一步 | 只显示空白表格 |
| 3 | 筛选无结果 | 保留筛选并允许重置 | 清空用户筛选 |
| 4 | `403` 缺功能权限 | 禁止访问页或只读降级 | 用空列表掩盖无权限 |
| 5 | `404` 或范围外 | 统一不可用状态 | 泄露对象是否存在 |
| 6 | `409` 冲突 | 展示冲突类型和恢复入口 | 静默覆盖或自动重试 |
| 7 | 网络/超时 | 错误说明、`request_id`、重试入口 | 自动重复写请求 |
| 8 | 服务端错误 | 稳定错误页和重试入口 | 猜测成功或继续提交 |

页面不得根据 HTTP 状态或 `message` 猜测冲突原因。`409` 必须按稳定业务错误码映射；`412`、`428` 和 `429` 是独立结果，不并入 `409`：

| HTTP | 稳定错误码 | 页面类别 | 前端行为 |
|---|---|---|---|
| `400` | `ORG_VALIDATION_FAILED` | 字段校验 | 标记字段、保留输入、聚焦首个错误 |
| `409` | `ORG_CODE_CONFLICT` | 业务冲突 | 定位编码字段并要求修改 |
| `409` | `ORG_PARENT_INACTIVE` | 业务冲突 | 重新选择启用父机构 |
| `409` | `ORG_CYCLE` | 业务冲突 | 禁止目标并重新选择 |
| `409` | `ORG_MAX_DEPTH_EXCEEDED` | 业务冲突 | 展示移动后深度，要求调整目标 |
| `409` | `ORG_HAS_ACTIVE_CHILDREN` | 业务冲突 | 先处理启用子节点 |
| `409` | `ORG_HAS_ACTIVE_MEMBERS` | 业务冲突 | 先迁移活动成员 |
| `409` | `ORG_ROOT_PROTECTED` | 业务冲突 | 阻止操作，不提供重试 |
| `409` | `ORG_INVALID_STATE` | 业务冲突 | 刷新当前状态后重新确认 |
| `409` | `IDEMPOTENCY_KEY_REUSED` | 幂等冲突 | 刷新页面并为新操作生成新 key |
| `412` | `ORG_VERSION_CONFLICT` | 版本过期 | 加载最新版本，由用户重新提交 |
| `428` | `PRECONDITION_REQUIRED` | 缺少前置条件 | 重新加载资源，不自动补提交 |
| `429` | `RATE_LIMITED` | 限流 | 按 `Retry-After` 提示，写操作不自动重试 |
| `500/502/503` | `ORG_SERVER_ERROR` | 服务异常 | 显示 `request_id` 和重试入口，不猜测成功 |

操作结果还应区分成功、字段校验失败、幂等重放、版本冲突、业务冲突和未知服务异常。后端新增错误码时，前端必须失败关闭为通用业务错误，不能落入成功态。

## 5. 关键页面与流程

### 5.1 机构管理

桌面端主界面采用树表格，窄屏切换为可访问的列表 + 展开详情或按层级筛选。

组件结论：

- Nuxt UI `UTable` 支持展开行，使用 `expandedOptions`、`getSubRows` 和 `getExpandedRowModel` 组成机构树表。
- 现有 `UDataTable` 是平面 `UTable` 编排，`DataTablePattern` 是平面远程列表查询，均不是树表。
- `UTree` 存在但当前只在 Showcase 使用，没有项目级适配器。
- 首期采用页面私有树表组合，不立即扩展公共 `UDataTable`；出现第二个真实复用后再评估公共化。

主流程：

1. 按权限加载树，显示当前数据范围和停用节点开关。
2. 新建：选择父机构，填写编码、名称、类型、排序、负责人和描述。
3. 编辑：仅修改基础资料；编码、层级和状态分别走独立动作。
4. 移动：键盘可访问的“选择新父机构”对话框是主路径；拖拽仅增强。
5. 停用/启用：使用同一状态动作，明确显示子节点和活动成员约束。
6. 删除：首期不提供删除或恢复入口，只提供停用与启用。

机构移动确认必须展示：

- 源机构和目标父机构。
- 移动子树高度与移动后深度。
- 是否超过四级、是否进入自身后代。
- 受影响用户和角色范围摘要。
- 版本冲突时要求刷新，不自动覆盖。

验收：

- 根节点不可普通创建、不可移动到其它父节点。
- 移动到自身、后代或超过四级时被阻止。
- 树搜索不返回范围外节点；必要时返回祖先但不可操作。
- 键盘可完成展开、选择、移动和取消；焦点在对话框关闭后恢复。
- 没有拖拽也能完成所有操作。

### 5.2 用户管理

用户列表展示用户名、显示名、所属机构、状态、角色摘要和最后更新时间。

用户编辑使用 Drawer，但资料编辑与授权变更分开提交：

| 区域 | 内容 | 提交语义 |
|---|---|---|
| 资料 | 姓名、机构、联系方式、状态为非密码资料时按契约 | 独立保存，使用独立版本前置条件 |
| 授权 | 角色绑定、范围、有效期 | 独立保存，展示防提权与影响摘要 |
| 凭证动作 | 重置凭证、强制退出 | 独立高风险动作，二次确认并审计 |

规则：

- 用户当前仅属于一个机构；不得出现“主属机构 + 多机构列表”的多机构编辑器。
- 角色绑定必须同屏显示角色和范围，不把角色做成无上下文 Select。
- 有效权限只展示后端计算结果和来源角色；前端不得猜测。
- 禁用本人、最后一个平台管理员、最后一个租户管理员和超出自身范围的授权必须被阻止。
- 关闭任一有未保存修改的区域都必须提示；两个区域不能隐式一起提交。

### 5.3 角色管理与权限矩阵

权限矩阵是独立工作区，不是普通 CRUD Drawer。

- 左侧角色列表支持搜索、受保护状态和启用状态。
- 右侧按领域/资源分组展示权限，支持行选择、组选择和 indeterminate。
- 权限来自权限目录，不允许自由输入权限码。
- 内置角色展示不可编辑/不可删除原因；需要调整时复制为派生角色。
- 保存前展示变更摘要：新增/移除权限、范围变化、预计影响用户数。
- 防提权提示必须在提交前出现，但以后端拒绝为最终结果。
- 窄屏切换为按资源分组的手风琴或分步编辑，不压缩成不可用表格。
- 表头、组和单元格必须有关联的可访问标签；键盘可切换和保存。
- 角色权限变更后，已登录用户按 `permissions_version` 及时失效。

验收：

- 任意角色都不能通过 UI 或 API 授予超出操作者权限的权限。
- 多角色有效权限展示来源和最终合并结果。
- 普通用户无法访问管理路由；审计员不能执行写操作。
- 受保护角色在 UI、路由和 API 三层均失败关闭。

### 5.4 数据字典

- 字典类型和字典项分别维护，不把主从实体混在一次保存中。
- 已被业务引用的字典项优先停用，不硬删除。
- 默认项必须保持启用；存在其他活动项时先迁移默认项，默认项为最后一个活动项时可停用并清除默认状态。
- 可预览 JSON 值和业务使用提示，但不建设第二套通用配置平台。
- 缓存刷新是明确动作，并显示版本或更新时间。
- 多语言和扩展属性属于 P2，不进入首期 HTML 原型范围。

### 5.5 公告管理

状态模型：

```text
draft ──> scheduled ──> published ──> withdrawn
  │           │              │
  └──────────>│              └──────> expired
              └──────x withdrawn
```

候选转换：

| 当前状态 | 允许动作 | 结果状态 | 说明 |
|---|---|---|---|
| `draft` | 保存草稿 | `draft` | 可重复编辑 |
| `draft` | 计划发布 | `scheduled` | 需要发布时间和受众快照 |
| `draft` | 立即发布 | `published` | 需要发布权限和幂等键 |
| `scheduled` | 系统按时发布 | `published` | 失败进入可观察失败态，不重复发布 |
| `scheduled` | 撤回/取消计划 | `withdrawn` | 需要独立权限和审计 |
| `published` | 撤回 | `withdrawn` | 不得原地修改已发布内容 |
| `scheduled` / `published` | 到期 | `expired` | 系统动作，作为不可回退状态 |

以上转换已由产品确认；未列出的转换不得由页面自行实现。

规则：

- `draft`、`scheduled`、`published`、`withdrawn`、`expired` 是公告生命周期状态。
- 预览快照不是生命周期状态；每次预览保存当时的标题、正文、受众摘要和生成时间。
- 草稿可编辑；已发布公告不得原地修改。发布后如需变更，必须另行确认版本化能力，不得直接覆盖已发布内容。
- 首期不默认加入“待审批”状态；需要审批流时单独评审。
- 正文使用白名单 HTML；预览区域不能执行脚本。
- 受众选择显示机构树、角色摘要、预计人数和最终范围，不只显示“按规则”。
- 发布和撤回使用独立权限、独立确认和幂等键。
- 定时发布必须显示用户本地时间和服务端 UTC 含义。
- 撤回后已阅读用户的历史记录保留策略必须明确。

验收：

- 无发布权限只能保存草稿或只读。
- 受众预览与后端最终计算结果不一致时有明确提示。
- 重复发布或撤回不会产生重复发布事实。
- 附件、链接和 HTML 预览经过安全处理。

### 5.6 审计日志

审计日志严格只读，列表支持时间、操作者、动作、资源、结果和 `request_id` 筛选。

审计详情优先使用独立页面 `/audit/logs/:eventId`，以支持深链接、刷新和关联事件筛选。最终以 `ENG-UI-03` 人工批准为准。

详情内容：

- 基本信息：event ID、时间、操作者、动作、资源、结果、`request_id`。
- 来源信息：IP/UA 只在安全允许且脱敏时展示。
- 变化摘要：字段差异、前后值摘要；敏感字段显示“已脱敏”。
- 关联操作：同一 `request_id` 的事件和后续事件。
- 不提供编辑、删除或普通清空按钮。
- 首期不提供导出、归档或合规删除入口；只支持保存和授权范围内查询。
- 页面不得宣称满足尚未定义期限的合规保留要求。

### 5.7 批量导入与冲突处理（P1）

```text
上传文件 → 选择导入类型 → 字段映射 → 预校验
→ 展示有效行 / 警告行 / 错误行 → 下载错误报告
→ 确认导入 → 异步任务进度 → 结果摘要 → 下载结果
```

- 不把“上传成功”当作“导入成功”。
- 预校验显示冲突类型，例如编码重复、机构不存在、角色不可授予。
- 部分成功语义必须由后端定义；前端逐行展示。
- 重试只针对可安全重试的任务，并使用幂等键。
- 大批量操作通过任务状态页，不阻塞浏览器刷新。

## 6. 原型门禁

### 6.1 HTML 原型基础包

必须先包含：

- 信息架构、导航、页面路径和权限说明。
- 统一列表/表单/详情/确认/状态矩阵。
- 机构树查看、创建、编辑、移动、启停和“不提供删除”的边界。
- 用户单机构归属、资料/授权分区提交。
- 权限矩阵搜索、保护状态、变更摘要、窄屏和键盘路径。
- 字典主从页面。
- 公告草稿、预览快照、计划发布、发布和撤回。
- 审计筛选与独立详情页。
- 批量导入 P1 流程草图。

### 6.2 HTML 原型复杂场景包

只制作四个复杂场景：

1. 机构树与移动确认。
2. 角色权限矩阵。
3. 公告发布、受众预览与撤回。
4. 审计事件详情。

HTML 原型必须绑定本仓库现有主题、密度、外观、字体和布局能力，至少检查：

- Light/Dark 与多主题。
- Comfortable/Compact 密度。
- 桌面、平板和窄屏。
- 键盘焦点、屏幕阅读器标签和减少动画偏好。
- loading、empty、filter-empty、403、404、409（两类）、网络/超时和服务错误。
- 机构树无拖拽主路径和权限矩阵窄屏路径。

HTML 原型完成后即可进入实现评审；不额外设置多角色原型签收门禁。

### 6.3 HTML 原型边界

原型工具已确认采用 HTML。首期不额外要求多角色签收、版本号或独立证据包。实现仍必须遵守本仓库 `DESIGN.md`、主题/密度/外观约束，并通过代码级键盘、窄屏和可访问性验收。

推荐组合：

1. 用 RuoYi / ruoyi-vue-pro 检查基础模块完整性。
2. 用 Ant Design Pro、Vben Admin、Soybean Admin 和 Arco Design Pro Vue 对比列表、表单、异常状态和信息层级。
3. 用 Keycloak / Casdoor / Authentik 理解 SSO、账号绑定、会话和管理边界。
4. 用 RAM/CAM/IAM 理解动作、资源、范围、有效权限和审计。
5. 回到本项目落地：布局、组件、Token、主题、密度、可访问性和状态语义以本仓库设计系统为准。

参考项目版本、许可证和维护状态必须在真正复用任何资产前单独核验。本文不授权复制源代码或视觉资产。

不推荐：

- 找一套后台模板直接复制页面。
- 同时混用 Ant Design、Arco、Element Plus 和 Nuxt UI。
- 复制参考系统的角色名、菜单树或数据模型。
- 把 Keycloak/Casdoor 管理界面直接嵌入业务应用。
- 用参考项目截图替代本仓库设计 Token 和状态规范。
- 先做全量 HTML 原型，再发现 API、权限或机构模型不成立。

## 8. 交互验收边界

- 页面和原型不创造第二套设计系统。
- 复杂页面优先复用现有模式和 Nuxt UI，不在页面复制原语。
- 所有管理页面必须具备键盘操作、可见焦点、错误文本、状态文本和合理语义标签。
- 所有危险操作必须说明影响并有明确确认文案。
- 所有列表必须区分空、筛选无结果、无权限、范围外、加载中和失败。
- 所有写操作必须覆盖 `401`、`403`、`404`、`409`、`412`、`428`、网络/超时和服务端错误。
- 高风险管理流程必须能追溯到 API 契约和审计事件。
- HTML 原型完成后仍须建立独立 L3 实现任务契约，不能在规划任务中直接改 `src/**`。
