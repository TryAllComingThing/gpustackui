## 1. 总体结论

方案方向正确，不需要推倒重来：

- 认证、业务授权和前端展示分层。
- 业务后端是授权事实源。
- RBAC + 机构数据范围。
- 机构作为第一个垂直切片。
- HttpOnly Session、CSRF、失败关闭和追加式审计。
- 复用 Nuxt UI 4、`UDataTable`、`DataTablePattern` 和 `ComplexFormPattern`，不创建第二套后台组件体系。

但本轮确认的决策主要仍停留在 `review-checklist.md`，没有同步落入 ADR、权限矩阵、机构 API 和交互文档。当前材料可以作为下一轮联合修订的输入，不能作为产品签收、OpenAPI 冻结或实现任务的事实来源。

## 4. 推荐关闭顺序

### 第 0 轮：建立唯一决策事实源

责任人：产品/架构负责人、安全负责人、后端负责人。

输出：

- `decision-log.md` 或升级后的 ADR。
- 每条决策包含决策人、日期、状态、证据、影响和替代方案。
- 旧评审报告明确标记为历史结论，清单只引用决策编号。

退出条件：不再存在“清单已确认但 ADR/API 未同步”的状态。

### 第 1 轮：ADR-001 定稿

必须先冻结：

1. 多租户和 `tenant_id` 硬边界。
2. 用户单机构。
3. 一个根机构、最大 4 级。
4. 唯一首期 IdP 和 OIDC 中介流程。
5. 身份绑定、JIT、破窗、退出和会话撤销。
6. `permissions_version` 与 `session_version`。
7. `audit_event_v1`、Outbox 和失败关闭策略。

输出：ADR-001 `ACCEPTED` 修订版和安全验收矩阵。

退出条件：ADR 无自相矛盾，产品、安全、后端、运维共同签收。

### 第 2 轮：角色权限矩阵 v0.2

输出：

- 租户级角色责任链。
- 唯一权限目录和内置角色保护字段。
- 可执行的有效权限算法与范围 Schema。
- `custom` 范围明细模型。
- 防提权、最后管理员事务不变量和并发测试。
- 统一 `403/404`、启停权限和权限撤销语义。

退出条件：每个权限码均能映射到 API 操作、页面动作、数据范围和测试用例。

### 第 3 轮：机构 API v0.2 与 OpenAPI

输出：

- `organization-api-contract-v0.2.md`。
- `organization.openapi.yaml`，使用 OpenAPI 3.1。
- 租户、单根、4 级、ID、状态、编码、ETag、幂等、事务和审计约束。
- 端点级请求/响应/错误/权限/审计样例。
